## 1. Result in one paragraph

Only three Bereitstellungsdatenarten carry Bescheiddaten that are machine-readable and numeric: `ESB`, `USB`, `GSB` (probably also `GEWMB`). Their Datenpaket is the ELSTER Bescheiddatensatz BDS-2, a fixed-width text format, not XML; the record layout is in EH ch. 15.4 (public), but the meaning of the numbers in it is in `Bescheidnr_*.zip` (developer area only). Every `Diva*`/`DIVA*`/`OZGBescheid`/`EPBescheid` kind delivers the Bescheid as a PDF Anhang plus a small metadata list; for these the metadata are the only machine-readable data, and the DIVA2 metadata carry one key figure-like field (`vorlaeufigkeitsmerker`). `Gewerbesteuerbescheid` is a PDF/A-3 with an embedded XML whose schema is published outside ELSTER (XÖV "XUnternehmen.Gewerbesteuer"); ELSTER's own documents do not define it. ERiC offers no decoding, rendering or comparison of Bescheiddaten.

## 2. What the Datenpaket and Anhang are, by construction

Both the receiver-side and the sender-side specification say the same thing, so this is firm:

- **DIVA kinds have no Datenpaket.** SSb-BEM section 5.4 (p. 18): the element `Daten` (which becomes the Datenpaket) "must always be present, except when the Ordnungsbegriff `diva` is set; then it is not allowed". The Bescheid travels as an Anhang (DIVA2: `Anhaenge`, with `DokumentHierarchieTyp` HAUPTDOKUMENT/NEBENDOKUMENT/VORBLATT/ANLAGE/AUSFERTIGUNG, SSb-DA p. 19) or, for DIVA stage 1 only, in the deprecated element `Verwaltungsakt/Pdf` (SSb-BEM 5.4.3-5.4.4, pp. 19-20, "Base64-kodierter digitaler Verwaltungsakt"). EH ch. 7.5 (p. 187 f.) also says the Bescheid is provided "im PDF-Format".
- **EPBescheid and Gewerbesteuerbescheid have no Datenpaket either.** SSb-BEM 4.4.3 (pp. 9-10) lists both among the Datenarten for which no `Daten` payload is allowed, and ch. 6 (Anhaenge) lists them as the Datenarten that carry Anhänge. EH ch. 9.15.4 (p. 424): "Nachrichten als PDF-Anhänge". The example `ElsterBereitstellung_EPBescheid.xml` has `MetaInformationen`, an e-mail text and one `application/pdf` Anhang.
- **ESB/USB/GSB/GEWMB are the Bescheiddaten kinds.** EH Table 9-9 (pp. 291-293): "Bescheiddaten (siehe Kap. 7.4) zu ... Einkommensteuerbescheiden / Umsatzsteuerbescheiden / Gewerbesteuerbescheiden / Gewerbesteuermessbescheiden, nicht rechtsgültig". EH 7.4.3 (p. 186): they "liegen dann in dem im Kap. 15.4 beschriebenen Bescheiddatensatzformat vor". "Not legally binding" is the key difference to the DIVA kind of the same tax.
- `OZGBescheid` and `OZGMitteilung`: "werden meistens als PDF geliefert" (EH Table 9-9, p. 293). "Meistens" is the only statement; no data format is defined **[not found]**.
- Sender may put `Xml` or `Base64` into `Daten` (SSb-BEM 5.4, p. 18). Default encoding when no `encoding` attribute is given: ISO-8859-15 (5.4.1). This explains `Datenpaket/Encoding` (ISO-8859-15 or UTF-8, SSb-DA p. 18). So for ESB the `Encoding` element is the only encoding hint; BDS-2 field lengths are character counts, not byte counts (EH footnotes 82-85, pp. 496-507).

### Layering after Otto

- Sender side (SSb-BEM 5.4.1): Base64 content is decoded, then encrypted and compressed. Stored object = compressed, then CMS-encrypted. The size fields in SSb-DA (`Datenpaket/Groesse`, `DateiGroesse`) are the size of the "kodierten, komprimierten und verschlüsselten Inhalts" (pp. 18-19); EH 9.2.1 (p. 280) adds "Base64-codierter Form" for the PostfachAnfrage size.
- OTTER delivers CMS/PKCS#7 EnvelopedData for the requesting Certificate (SSb-OTTER 5.12.4.3, see research 02); HTTP `Content-Encoding: gzip` in OTTER is transport compression only (SSb-OTTER lines on "gzip-Komprimierung", OAS).
- Otto (API, status codes `OTTO_ENTSCHLUESSELN_FEHLGESCHLAGEN`, `OTTO_DEKOMPRESSION_FEHLGESCHLAGEN`, API p. 260) decrypts and decompresses itself when it holds the Certificate. With the "Abholzertifikat" variants (`OttoEmpfangBeginnenAbholzertifikat`, `OttoDatenAbholen`) Otto returns the still-encrypted data and the caller decrypts with `EricDekodiereDaten` (API pp. 73-74, 224-232). So **[inference]**: with the normal flow (Certificate = Zertifikat in the soft-PSE) KIECLI gets the plain Datenpaket bytes from Otto in the stated `Encoding`, with no Base64 or gzip step of its own; the compression algorithm is not named in the Datenabholung documents (the legacy TransferHeader says `Kompression` = GZIP). To be confirmed on a real sample (ticket 03).

## 3. The ESB/USB/GSB record format (BDS-2), EH ch. 15.4

Public in the ERiC documentation zip (EH pp. 496-508). Structure, in my words:

- A text file of fixed-width records, each ending in CR LF. Record types by the first character: `V` (Vorsatz, one), `D` (Datenteil, header of a Teilbescheid), `W` (Werte, repeated; count in `D` field 17).
- **Vorsatz** (Tables 15-6 for version `0003` and 15-7 for `0004`): Satzart, Versionsnummer (positions 2-5), Bundesfinanzamtsnummer, Art der Ordnungsnummer, Steuernummer, Unterfallart (10/12 ESt, 20/22 Gewerbesteuer, 50/51 USt), Zeitraum (Veranlagungsjahr `jjjj`), Vorgang, Übermittlungs- and Erstellungsdatum/-zeit, Art der Steuerdaten (`EB`, `UB`, `GB`, `GF` for Stadtstaaten), Rechenzentrum address block, Testmerker, Telenummer of the original return, HerstellerID, IdNr and second IdNr (Ehegatte/Partner B), Transfer reference. Version `0004` differs from `0003` in the Vorgang values (adds `03` = laufende Vorauszahlungen and `05` = nachträgliche Vorauszahlungen for ESt, `01` = NRW) and in the last field (32-character ELSTER-Transfer-ID instead of a 19-character transfer ticket); the record length grows from 320 to 332 characters plus CR LF.
- **Datenteil `D`** (Table 15-8, version `0003` only documented): same identification block, `lfd. Nr.` (at most three `D` records: one per Teilbescheid "Festsetzung", "Abrechnung" and "VZ" (Vorauszahlung)), Anzahl der Folgesätze `W`, Steuerart (`EST`, `GST`, `UST`). The table says "derzeit unterstützt: 10 Einkommensteuer" for Unterfallart in `D`, so ESt is the documented case; USt and Gewerbesteuer appear in the Vorsatz and Steuerart only.
- **Werte `W`** (Table 15-9, "Stand 01.06.2007"): `Nummer` (10 characters: 3 category + 7 number), `Sub-Nummer` (15, "für Gewerbesteuerbescheide", unused for ESt), `Format` (`N` integer, `P` two decimals, `V` four decimals, `C` text), `Länge` (3), `Wert` (variable), `Textlänge` (3, "0 as long as no Bescheidtexte are delivered"), `Bescheidtext`. Amounts carry no decimal separator: the handbook's examples show 0.32 as `P` with value `32` and -0.03 as `P` with value `-3`. **Note**: the three examples on p. 508 show 25 characters before the format letter and no `Textlänge`; either the examples omit it or Nummer plus Sub-Nummer is the 25 characters. Needs a real sample **[inference]**.
- **What a number means is not in the record format.** The meaning of each `Nummer` (festgesetzte Steuer, Abrechnung, Vorauszahlungen, Vorbehalt der Nachprüfung, Vorläufigkeit) is in the Bescheidwertnummern XML files, one per Steuerart: `Bescheidwertnummern_ESt.xml`, `_GSt.xml`, `_USt.xml`, in the package `Bescheidnr_*.zip` (EH Table 4-5, p. 78, "Dokumentation Bescheidwertnummern"; EH 9.1, p. 277: "Im ELSTER-Entwickler-Bereich ... im Paket Bescheidnr_*.zip"). It is not in the ERiC documentation zip (searched: no file with `Bescheid` in its name).
- Version scheme: the format version is in the record (`0003`, `0004`), the Veranlagungsjahr is a field (`Zeitraum`). Whether Bescheidwertnummern change per Veranlagungsjahr is not stated; the zip is "Aktuelle Version" without a year (EH Table 4-5) **[not found]**.

## 5. What ERiC offers for Bescheiddaten

Nothing beyond transport. Checked the API reference function list (EricXxx, EricMtXxx, OttoXxx) and the EH:

- No function parses, renders, compares or validates a Bescheiddatensatz or a Bescheid. The only Bescheid-named functions are `EricMakeElsterStnr`/`EricFormatStNr` and the Einheitswert-Aktenzeichen helpers (steuernummer formatting).
- Relevant functions are `EricBearbeiteVorgang` (PostfachAnfrage/Bestätigung), the Otto family (fetch, decrypt, decompress), `EricDekodiereDaten` (decrypt only, for the Abholzertifikat variants), `EricHoleZertifikatFingerabdruck` (CEZ fingerprint for the "send-NoSig" retrieval path).
- ERiC checks only the Datenabholung request/response XML (plug-in `checkElsterDatenabholung`, `datenartVersion` 32; `Datenartversionmatrix.ods`). The Datenpaket content, BDS-2 or otherwise, is outside ERiC's validation.
- Consequence: **KIECLI must parse BDS-2 itself** (a small, fixed-width parser) and must carry or load a Bescheidwertnummer table itself; nothing in ERiC substitutes. For the PDF/A-3 Gewerbesteuerbescheid, ERiC has nothing either.

## 6. Coupling between the return filed and the Bescheiddaten kinds

EH 7.4 (pp. 184-186): ESB/USB/GSB exist only if the Erklärung was filed with `Rueckuebermittlung bescheid="ja"` (EDS-XML v2). The Zuordnungskriterium decides who can fetch: with `send-Auth` and no `SchluesselRueckuebermittlung` ("nur ein Bearbeiter") it is the same Mein-ELSTER-Zertifikat that filed; with a client-generated certificate (CEZ) as `SchluesselRueckuebermittlung` ("mehrere Bearbeiter") it is that CEZ's fingerprint, fetched with `send-NoSig` plus `Fingerprint` (Tables 7-1, 7-2). So **[inference]**: KIECLI with the user's Certificate sees an ESB only for returns filed with it (or for which the account was the recipient); an ESB bound to another software's CEZ is not visible. The public ELSTER FAQ ("Bescheiddaten" 180 days, 60 days after Abholung, see research 02) and forum threads (DATEV/WISO "nur mit der Software abholbar") are consistent with this, but they are secondary sources.

## 8. Existing open-source clients

- **haben** (`postfach.ts`): parses only the Anfrage metadata (`bescheiddatum`, `steuernummer`, `veranlagungszeitraum`, anhaenge); asks for `ESB` and `DivaBescheid*` but does not decode the ESB Datenpaket. Its roadmap names the Bescheidwertnummern list as missing.
- **viking** (MIT): `abholung.nim` reads `bescheiddatum` and other meta, fetches objects through Otto; no Bescheid decoding.
- No open-source BDS-2 or Bescheidwertnummer parser found (GitHub code search for `BDS2` and `Bescheidwertnummer`: only haben's roadmap line). So the BDS-2 parser and the number table have no prior art to borrow.

## 9. Open points

1. **Number list.** The Bescheidwertnummern files are the only way to name key figures for ESB/USB/GSB (ticket 02). Until read: unknown which numbers mean festgesetzte Steuer, Abrechnung (Nachzahlung/Erstattung, Fälligkeit), Vorauszahlungen, Vorbehalt der Nachprüfung, Vorläufigkeit; and whether the last two exist as numbers at all.
2. **BDS-2 details.** Datenteil and Werte are described only for version `0003`; Vorsatz for `0003` and `0004`. `D` documented for ESt only. Examples on EH p. 508 do not match the table layout (Textlänge missing). Which version real ESB/USB/GSB deliveries use today, and what `Sub-Nummer` carries for GewSt. Settle with real samples (ticket 03).
3. **Layering.** Confirm on a sample that Otto output is the plain text in `Encoding` (no Base64 or gzip left) for the Certificate flow, and what the object looks like for `Anhang` PDFs.
4. **Vorläufigkeit in DIVA2.** `vorlaeufigkeitsmerker` is optional and absent from the 9.4/9.5 tables. Real `PostfachAnfrage` responses will show when it is present. It is a Meta value, so a faithful JSON copy keeps it as delivered.
5. **Gewerbesteuerbescheid.** Read the Bescheid's own XSD and spec (xrepository.de, "XUnternehmen.Gewerbesteuer"; archive 1.2.2-1.3 and later) and settle whether extracting an embedded XML from PDF/A-3 is within "machine-readable, never PDF text extraction". Check licence (none stated).
6. **GEWMB and the extra table-9.4 names** (`ESSGS`, `ESTGS`, `EURS`, `FEIGS`, `GEWGS`, `GMB*` ...): format and relevance unknown. A real PostfachStatus per Datenart will show if any appear for a taxpayer.
7. **Who sees ESB.** Visibility depends on the filing combination (section 6). Verify with a test-system return filed with `bescheid="ja"`.
8. **KSt, FEIN, ErbSt, SchenkSt, Grundsteuer** and all other Verwaltungsakte are PDF-only plus Meta; no ESB-style data kind exists for them in EH Tables 9-8 and 9-9.
9. **Retention.** `ESB` deletion: "60 days after Abholung" is the only public statement (research 02); per-record `verfuegbarbis` governs.
